# Implementation Plan: Мегдан (MVP, вълна 1)

## Overview
Публикуван Artifact с лоби, стаи по код и 4 ходови игри за 2–6 приятели. Състоянието живее в `db` като append-only лог от ходове; всеки клиент възстановява и валидира играта детерминистично. Спецификация: `SPEC.md`.

## Architecture Decisions
- **Лог + replay вместо споделен state:** без конфликти при запис, ход извън ред просто не минава валидация, повторното свързване е безплатно.
- **Адаптер за store (claude / local):** E2E и локална разработка без claude.ai; същата API.
- **Без build:** ES modules, публикувани като supporting files на артефакта.
- **Само собственикът пише профила и статистиката си** (db rules `{self}`); ELO се смята детерминистично от рейтингите, записани при старт.
- **`room` само за присъствие** (кой е онлайн); истината е в `db` чрез `onSnapshot`.

## Risks and Mitigations
| Risk | Impact | Mitigation |
|------|--------|------------|
| Конфликт при запис (няма транзакции) | Med | Всеки документ има един пишещ (ходове, чат, членство по играч); дубликати се игнорират при replay |
| `db` / `room` не работят в мобилното приложение Claude | Med | Проверка след публикуване; поканата насочва към браузъра |
| Права: приятели извън организацията пишат само като Editor и без публичен линк | High | Инструкция за покана: по имейл като Editor, без публичен линк; ясна грешка в UI при отказан запис |
| Таймаут, записан от няколко клиента едновременно | Low | Таймаутът е обикновен ход с индекс; дубликатът е невалиден при replay |
| Скрити карти видими в базата | Low | Приемливо за приятели (в SPEC) |
